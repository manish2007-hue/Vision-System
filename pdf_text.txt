1. PROBLEM STATEMENT
1.1 The Core Problem
Industrial robots use cameras to “see” objects — to pick them up, sort them, inspect them, or
play chess. But these cameras are dumb. They don’t see like humans do. They see pixels —
numbers representing brightness and color. When the lighting changes, the numbers change,
and the robot gets confused.
Real-world scenario from SVR Robotics (visited July 31, 2026):
SVR builds educational and industrial robots. Their robots use vision sensors (cameras) to
detect objects, recognize shapes, and perform pick-and-place tasks. They told us directly:
“When sunlight comes from the window, shadows appear on the objects. The robot’s camera
sees the shadow as a separate object, or the shadow changes the shape of the object. At
different times of day, the same object looks completely different to the camera.”

3. OUR SOLUTION — THE MIND-BLOWING PART
3.1 The Core Idea
We teach the AI to be “lighting blind.”
Just like a human can recognize a triangle in sunlight, in darkness, in shadow, and under a
yellow bulb — our AI learns to ignore lighting variations and focus ONLY on the shape’s
geometry (edges, angles, curves).
Two weapons:
Weapon 1 — Pre-processing (Clean the image before AI sees it): The raw camera image is
messy — shadows, uneven brightness, color shifts. Before the AI analyzes it, we run it through a
mathematical cleaning pipeline that normalizes the lighting. The AI always sees a “clean”
image, regardless of actual conditions.
Weapon 2 — Smart Training (Make the AI lighting-proof): During training, we show the AI the
same shape under hundreds of different lighting conditions (generated automatically by the
computer). The AI learns: “Brightness changes, shadows appear, colors shift — but the SHAPE
stays the same. Ignore everything except the shape.”

3.3 Stage 1 — Lighting Normalization (CLAHE)
What it does: Takes an unevenly lit image and makes it look evenly lit.
How it works (simple language):
1. Convert image from BGR (normal color) to LAB color space
L = Lightness (how bright each pixel is)
A = Green-Red color info
B = Blue-Yellow color info
2. Apply CLAHE only on the L channel (brightness)
CLAHE divides the image into small tiles (8×8 grid)
For each tile, it equalizes the brightness independently
Dark tiles get brighter, bright tiles get dimmer
Result: entire image has uniform brightness
3. Convert back to BGR
Colors are preserved (we only changed brightness, not color)

Python code:
import cv2
def normalize_lighting(image):
    # Convert to LAB color space
    lab = cv2.cvtColor(image, cv2.COLOR_BGR2LAB)
    l, a, b = cv2.split(lab)
    
    # Apply CLAHE to L channel (brightness only)
    clahe = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8, 8))
    l_normalized = clahe.apply(l)
    
    # Merge back and convert to BGR
    lab_normalized = cv2.merge((l_normalized, a, b))
    result = cv2.cvtColor(lab_normalized, cv2.COLOR_LAB2BGR)
    return result
3.4 Stage 2 — Shadow Compensation
What it does: Finds shadow regions in the image and brightens them to match the rest.
How it works:
1. Convert to HSV color space
H = Hue (what color)
S = Saturation (how vivid)
V = Value (how bright)
2. Shadows have low V (dark) but keep their H (color)
3. Find all pixels with V below a threshold → these are shadow pixels
4. Calculate the brightness difference between shadow and non-shadow regions
5. Multiply shadow pixels’ brightness to match non-shadow regions
6. Result: shadows disappear
Python code:
import cv2
import numpy as np
def remove_shadows(image):
    hsv = cv2.cvtColor(image, cv2.COLOR_BGR2HSV)
    h, s, v = cv2.split(hsv)
    
    # Find shadow regions (dark areas)
    _, shadow_mask = cv2.threshold(v, 60, 255, cv2.THRESH_BINARY_INV)
    
    # Clean up the mask
    kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
    shadow_mask = cv2.morphologyEx(shadow_mask, cv2.MORPH_CLOSE, kernel)
    
    # Calculate brightness correction ratio
    non_shadow_mean = np.mean(v[shadow_mask == 0])
    shadow_mean = np.mean(v[shadow_mask == 255]) + 1  # avoid division by 
    ratio = non_shadow_mean / shadow_mean
    
    # Brighten shadow regions
    v_corrected = v.astype(np.float32)
    v_corrected[shadow_mask == 255] = np.clip(
        v_corrected[shadow_mask == 255] * ratio, 0, 255
    )
    
    # Merge and convert back
    hsv_corrected = cv2.merge([h, s, v_corrected.astype(np.uint8)])
    return cv2.cvtColor(hsv_corrected, cv2.COLOR_HSV2BGR)
3.5 Stage 3 — Shape Detection (Triple-Method Voting)
The problem: Using only one method to detect shapes fails. approxPolyDP alone confuses
hexagons with circles.
Our solution: Use 3 independent methods and let them vote. Majority wins.
Method 1: Contour Vertex Count
perimeter = cv2.arcLength(contour, True)
approx = cv2.approxPolyDP(contour, 0.025 * perimeter, True)
num_vertices = len(approx)
# 3 = Triangle, 4 = Square/Rectangle, 5 = Pentagon, 6 = Hexagon
Method 2: Circularity Ratio
area = cv2.contourArea(contour)
perimeter = cv2.arcLength(contour, True)
circularity = (4 * 3.14159 * area) / (perimeter ** 2)
# Circle   = ~1.00 (> 0.92)
# Hexagon  = ~0.91 (0.82 - 0.91)
# Square   = ~0.785
# Triangle = ~0.604
This is the KEY method that solves the hexagon ≠ circle problem. A circle’s circularity is
always > 0.92. A hexagon is always < 0.91. Clear mathematical separation.
Method 3: Hu Moments (Template Matching)
We compare the detected shape’s Hu Moments against pre-saved templates of perfect shapes.
Hu Moments are invariant to scale, rotation, and translation.
